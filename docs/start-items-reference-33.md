## 闪光与墨水：已确认效果，未确认获取和投掷

本轮实际查看每0.5秒的2340–2351与4422–4433原帧联系表 `flash-01/02.jpg`、`ink-01/02.jpg`，并打开2340.00、2340.50、2347.00和4424.00原帧。

- **39:00.00→39:00.50：** 学生桌前视野骤变近乎全白；HUD也基本不可读。39:05.50仍很白；39:06–39:08逐渐恢复抽屉、双手与HUD，恢复后仍有空间烟雾。白闪覆盖与烟团是两种效果，不能只放一团烟代替致盲。
- **受影响对象：** 上述明确是学生第一人称，不能只给老师加闪光干扰。此处可能有多人连发，因此“约五秒全白再渐退”仅为这个可见序列，不是单枚闪光弹准确时长。
- **73:42.50：** 老师在黑板边时，视野中央突然出现浓黑墨水飞溅。大片黑色不透明中心、细长液滴、边缘高光；四周场景与大部分HUD仍可见。
- **73:43–73:46：** 墨水持续遮挡中心；老师仍在写板书，体力恢复，随后转身走动。它不是冻结全部操作的眩晕。
- **73:47–73:50：** 中间开始透出场景、黑色逐渐淡掉。73:50.50又出现橙色泡泡爆裂飞溅，不能把随后橙色覆盖计入墨水持续时间。

未看到这两个物品被本视角从抽屉拿出、手持、释放的连续链，因此目前**不能确认瓶身/弹体外形、具体获取位置、是否共用抽屉池、点击与蓄力关系、碰地或碰人触发、准确引信、影响半径、计分**。不要把它们编成每局自带快捷技能并称“原版一致”。本轮没有修改运行时代码。


## 本轮实现与核验（2026-11-07）

- 用户否定新生成的菜单图后，已撤下生成图。菜单改用与视频同一画面的官方 Steam 插画原图：`https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/5175310/370926e20f12ffa7ccb3b276b01651cd2eb620b6/library_hero_2x.jpg`，3840×1240。使用的是清晰横幅原图，并非完整16:9视频截图；右侧裁切与黄色侧栏在实际菜单检查过，不能称为原版完整UI资产。
- 主菜单不创建/运行3D场景。进入准备弹窗才加载模型，进入校园后集合，中心瞄准红色上课铃按E，30秒入座，再开始10分钟回合。实际浏览器验证铃E提示、准备倒数和正式计时；修复铃的可选网格被静态合并移走导致无法按下。
- 准备期座位按参与者保留；正式开课后仍能坐空位。电梯切换仅在集合期，避免课中换图清空回合。
- 闪光弹和墨水瓶接入物品池及实际投掷；视觉分别为白闪、中央浓黑墨迹并保留周边视野。实际鼠标短按投掷、受影响倒数、暂停冻结、恢复和消退已检查，控制台无警告/错误。具体引信、强度与作用范围仍是开发参数，并未核实为原版精确数值。
- 近墙墨水首帧破碎后仍保留手部甩出动作时间。被绑泡泡实际长按约4.7秒后松手成功释放，4秒生命期及10秒冷却按模拟时间推进，渲染无错误。

## 地图纠正

用户指出地图整体不对。重新查看开头6.5、10、14、20、30秒及进入教室的34、41、44秒：

- 原走廊不应是两侧连续透视玻璃。改为教室侧半磨砂隔窗、外侧一个窗及长涂鸦墙，上课铃置于教室侧实体墙柱。走廊净宽由2.25米改3.15米，教室/办公室/电梯原内部尺寸保留，两端用真实回墙闭合。该尺寸为画面比例重建，不是原作测量数据。
- 修复电梯口上部露天；增加可见封墙且与碰撞高度一致；新外墙、柜子和地坪都与碰撞同步。
- 窗框由粗蓝型材改细灰绿，窗帘转暗青灰；光照与水磨石去黄，统一新增走廊地坪UV密度；前方红字不再与黑板相互遮挡。
- 实际渲染检查了走廊、普通教室及阶梯教室；真实规则控制的办公室→前门→教室→后门→电梯路径到达终点。原版素材/人物/建筑比例仍有差异，不写为一比一完成。
- 全套168项规则与模型测试通过（后续只改标语位置/屋顶接缝，再跑18项地图回归通过）。静态资源检查28源码/60引用通过。

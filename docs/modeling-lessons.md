## 五类故障：现象、原因边界、修复与验收

### 1. 胸肩白片出现碎三角

- **已观察**：`qa/screenshots/model-first-08.png` 中多个远近学生的白色胸肩片出现蓝色破口与零碎白三角。
- **不能直接断言**：单张截图不能分辨相交、近共面深度冲突、错误绕序、材质分组或批处理属性丢失。当前代码已改为连续肩片，旧截图不证明新版仍有同样错误。
- **检查顺序**：用纯色无光照材质隐藏蓝色底壳，单看白片；再恢复底壳检查表面交线；对比合并前的单个角色与合并后的场景实例；最后用线框与法线材质检查网格。如果单体正确而批处理错误，先查 group 范围、index 与 position/normal/color 的一一对应。
- **修复原则**：同一件衣服的颜色区域优先共用连续衣壳，使用材质分区、贴图或顶点色。必须有实体叠片时，贴片需沿真实底壳表面构造，并检查三角面内部也保持间隔；仅给顶点加一个正偏移不保证不同三角划分的面不会穿插。不要用提高细分或关闭深度测试掩盖原因。
- **验收**：相同模型在独立检视页与实例化场景都通过正面、侧面、背面及俯仰检查；转动镜头时无闪烁；呼吸和抬臂时不出现破口。不能只验收一个静止正面。

### 2. 眼球根部埋入脸，实际眼白变小

- **代码事实**：本次读取的 `characters.js` 使用分离的扁椭球眼白，固定根部位置与面部轮廓相交；眼白尺度不是最终可见面积。没有证据支持直接把某个百分比称为原作尺寸。
- **诊断**：同角度分别渲染完整脸和暂时隐藏脸壳的眼睛，比较被遮掉的区域；侧面查看根部深度、鼻梁侧遮挡与外眼角。先检查眼球位置、转角和眼周曲面，再决定是否放大。
- **修复原则**：以可见眼裂/眼白轮廓为目标，协调脸壳、眼球深度和眼睑遮挡；动态五官可以分件，关键是接触关系连续。不要把“所有网格必须焊成一体”写成规则。
- **验收**：正面、三分之四和侧面均无眼白突然缩小、边缘断裂或整体凸出；眨眼及视线偏移后仍贴合。使用与参考近似的视角，避免焦距造成的假比例。

### 3. 眉、嘴像漂浮的线

- **代码事实**：本次读取的眉与嘴沿固定局部 z 布置，而脸部是弯曲表面；眉还会独立升高和旋转。固定深度存在接触不一致的风险，并不等于每一帧都已确认穿帮。
- **修复原则**：沿眉线/唇线每个控制点采样脸部位置与法线，用局部法线的小偏移放置；运动后重新贴面或使用随脸变形的面片。Blender 可用 Shrinkwrap 思路，程序几何可用相同的解析曲面或射线投射。偏移量按画面可读性与模型尺度调试，不写死成跨项目常数。
- **验收**：45°、近侧面和仰角看不到明显空气缝，也没有线条埋进皮肤；眉毛上扬、嘴型变化后仍成立。只在正面能看见，不算通过。

### 4. 头发像帽檐或头盔

- **已观察**：旧截图男生刘海是横向厚块，女生冠部过平，前额、侧鬓与后脑的形体层次不清。
- **代码事实**：本次读取的侧分刘海来自六个截面的五边横截面。增加段数只会更密地插值这个控制形，不能自动生成正确的侧分与发束走势。
- **修复原则**：先用单色轮廓对照正面、侧面、三分之四和背面，分别调整颅顶弧、前额外伸、左右分缝、太阳穴与耳边收口；再加少量主发束与清楚的边界厚度，最后做细分和法线。外层轮廓圆滑与内部几何分件并不矛盾，但分件接缝应被设计过的交叠遮住。
- **验收**：关闭纹理和高光后仍能辨别发型；侧面没有悬空直板；背面无空壳穿孔；多角度大形通过之后才添加沟槽细节。

### 5. 远处学生发型与动画重复

- **确定原因**：本次读取的 `classroom.js` 使用 `seed = 3 + seat.id % 3`，而普通女生条件为 `seat.id % 3 === 0`。因此普通女生都收到 seed 3，同步选择马尾；种子还控制动作相位与眨眼周期。`templateFor` 的 key 已包含 variant、seed、standing，不能误记为缓存遗漏种子。
- **修复原则**：将稳定身份种子、有限外观变体和动画相位分开。外观可以复用少量模板，动作相位由独立身份散列产生；不必为每个学生复制整套几何。身份和座位可以相关，但不能把人物性别筛选与外观模运算绑定到同一个余数。
- **验收**：输出每个座位的身份、发型与相位清单；看整班连续数秒，确认相邻学生不成排同步。种子相同需可复现，换种子应影响允许变化的字段，缓存数量保持有界。

## 建议持久化的工作顺序

1. 先确定参考来源和已实际看过的角度。透视截图只能提供比例关系，不当作准确三维尺寸。
2. 用固定镜头和中性材质验大形：头、肩、脸、头发、坐姿和桌椅接触；大形不通过时不加微细节。
3. 每次只定位一种错误：轮廓、相交、法线、材质属性、动画接触或实例身份。保留故障图与修复图。
4. 独立模型通过后，必须再验真实场景中的合批、色彩管理、距离和动画。模型检视页正确不能替代最终场景检查。
5. 把“已验证原因”和“待验证假设”分别记录；持续更新，不把旧截图问题自动带到新版，也不将第三方教程的存在当作已经学习其视频内容。
